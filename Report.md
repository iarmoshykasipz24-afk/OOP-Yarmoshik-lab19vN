## Склад проєкту
- `user_not_found_exception.py` - власний виняток `UserNotFoundException(Exception)` з властивістю `username` і підтримкою серіалізації (`__reduce__`).
- `result.py` - узагальнений `Result[T]` (`Generic[T]`) з властивостями `is_success`, `value`, `error` та фабричними методами `success`, `failure`, `failure_from_exception`.
- `user.py` - модель користувача.
- `user_service.py` - `UserService`: `get_user` (виняток) і `register_user` (`Result[bool]`).
- `main.py` - демонстрація обох підходів.

## Консольний вивід
```
=== Метод з винятком: get_user ===
Знайдено: User(username=ivan)
Помилка: Користувача 'petro' не знайдено. (username = petro)

=== Метод з Result[T]: register_user ===
Успішна реєстрація: успіх (value = True)
Ім'я вже існує: помилка - Користувач 'ivan' вже існує.
Занадто короткий пароль: помилка - Пароль занадто короткий (мінімум 6 символів).
```

## Висновок: виняток чи Result
- **`get_user` + `UserNotFoundException`.** Запит на конкретного користувача, якого немає, означає, що метод не може виконати основну задачу (повернути `User`). Виняток перериває звичайний потік і не дає продовжити роботу з відсутнім об'єктом. Властивість `username` зберігає контекст помилки.
- **`register_user` + `Result[bool]`.** Дубль імені чи короткий пароль - очікувані, часті помилки вводу. Викидати для них винятки було б зайвим: `Result` робить невдачу частиною результату методу й повідомляє причину через `error` без `try-except`.

## Відповіді на контрольні запитання
1. **Навіщо власні винятки?** Вони описують специфічні помилки предметної області, дозволяють ловити їх окремо від загальних, нести додаткові дані (`username`) і роблять код зрозумілішим.
2. **Які конструктори реалізовувати?** Без аргументів, з повідомленням, з повідомленням та внутрішнім винятком (у Python внутрішній виняток задається через `raise ... from ...`), а також підтримка серіалізації (`__reduce__`, щоб працював `pickle`).
3. **Патерн Result.** Метод повертає об'єкт, що містить або успішне значення, або інформацію про помилку. Доцільний для очікуваних, частих сценаріїв невдачі (валідація вводу, відсутність елемента), де виняток був би надмірним.
4. **Що через винятки, що через Result?** Винятки - для виняткових ситуацій і порушення контракту методу (неможливо виконати основну дію). `Result` - для передбачуваних сценаріїв невдачі, які викликач має обробити явно.
